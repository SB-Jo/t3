   - **현재 구조**: Hop 1에서 삼성노트 메모(`"A사: 3분기 반품 현황 요청 → 민수 님이 정리하기로"`)를 찾고, Hop 2에서 민수 메일(`"정리본 공유드려요 / 첨부: 3분기_반품현황.xlsx"`)을 찾음.

## Part 2. 검색 아키텍처 심층 비교: BM25 vs. Dense RAG vs. KG vs. Weave Hybrid

결선 Q&A에서 심사위원이 반드시 물어볼 **"왜 기존 키워드 검색(Finder), 일반 벡터 RAG, 혹은 삼성 PDE(Knowledge Graph)만으로 안 되고 Weave의 파이프라인이 필요한가?"**에 대한 완벽한 기술 비교 정리입니다.

### 2.1 4대 검색 패러다임 장단점 비교 매트릭스

| 비교 축 | ① 키워드 검색 (BM25 / Lexical) | ② 일반 임베딩 검색 (Dense RAG / Bi-Encoder) | ③ 지식 그래프 (KG / 삼성 PDE·RDFox / HippoRAG) | ④ Weave Hybrid (Query Rewriting + Reasoning Embedding + Metadata Filter) |
|---|---|---|---|---|
| **핵심 원리** | 질의와 문서 간 정확히 일치하는 단어(Token) 빈도(TF-IDF) 매칭 | 질의와 문서를 단일 의미 공간의 벡터로 변환해 코사인 유사도(표면적 의미 유사성) 계산 | 문서에서 엔티티(Entity)와 관계(Relation)를 추출해 트리플 `(주어, 술어, 목적어)` 그래프로 저장 후 규칙(Datalog)/경로 탐색 | **사전 준비(00)**에서 원문+벡터+메타데이터 색인 → **질의 시점(02~03)**에 질문을 하위 질문으로 분해(Query Rewriting)하고, **Reasoning Embedding**과 **메타데이터 필터**를 결합해 연쇄 탐색(Multi-hop) |
| **장점 (Pros)** | - 고유명사·파일명·숫자·정확한 코드 매칭에 압도적 정확도<br>- 색인·검색 연산이 매우 가볍고 빠름<br>- 결과 설명 가능성(어떤 단어가 매칭됐는지) 명확 | - 표현이 달라도 의미가 비슷하면 검색 가능 (예: `"강아지"` ↔ `"반려견"`)<br>- 스키마 정의 없이 자유로운 자연어 원문 색인 가능<br>- 질의당 1회 인코딩으로 온디바이스에서 고속 검색 | - **정해진 온톨로지/스키마 내에서는 다단계(Multi-hop) 관계 추론이 매우 정확하고 설명 가능함**<br>- 구조화된 질의(SPARQL) 및 논리 규칙(Datalog) 적용 가능 | - **비정형 일상 대화·사진·메모 사이의 암묵적 단서(Implicit Clue)**를 사전 스키마 없이 즉석에서 연결<br>- 날짜·앱·발신자 등 확정 조건은 **메타데이터 필터(Symbolic)**로 칼같이 거르고, 맥락 연결은 **Reasoning Embedding(Neural)**으로 수행해 정확도와 온디바이스 효율 동시 달성 |
| **치명적 단점 (Cons)** | - **어휘 불일치(Vocabulary Mismatch)**: `"집들이"`로 검색하면 `"이사 기념 저녁"`을 절대 못 찾음<br>- 단어만 겹치는 오답(예: `"집들이 선물 메모"`, `"화이트 와인 고르는 법"`)이 최상위에 노출됨 | - **단일 홉(Single-hop) 한계**: 질문과 최종 정답 사이에 중간 단서(날짜, 담당자, 별명)가 빠져 있으면 질문 벡터 주변에 정답이 오지 않음<br>- **표면적 유사성 함정**: `"집들이 때 마신 화이트 와인"`을 검색하면 다른 날(회식 때) 마신 와인 사진이나 와인 추천 글이 1위로 올라오고, 정작 와인 단어가 없는 `"지은 카톡(날짜 단서)"`은 벡터 공간에서 멀리 떨어져 누락됨 | - **사전 정의된 스키마(Schema Rigidity) 한계**: 미리 정의된 엔티티·관계 규칙에 맞지 않는 일상 표현(예: `"이사 기념으로 우리 집에서 저녁 먹자"` = 집들이, `"피부과 원장님이 추천해 준 재생 크림"`)은 그래프 간선(Edge)으로 연결되지 않음<br>- **온디바이스 색인 비용(OpenIE Cost)**: HippoRAG처럼 모든 자유 텍스트를 그래프로 만들려면 색인 때마다 무거운 LLM을 돌려야 해 모바일 배터리가 감당 불가 | - 홉(Hop) 수가 늘어날수록 지연시간이 선형 증가할 수 있음 → **해결책**: 모바일 일상 기억은 대부분 2~3홉 이내(날짜/인물/대상 확인 → 원문/사진 특정)로 수렴하며, 최대 홉 수(Max 2~3 Hops)와 조기 종료(Early Stopping) 조건으로 지연시간을 1초 이내로 통제 |

### 2.2 왜 "단순 Hybrid (BM25 + 일반 Dense Embedding)"로도 안 되는가?
- 흔히 검색에서 말하는 **단순 하이브리드(Single-hop Lexical + Dense RRF 결합)**는 BM25 점수와 일반 임베딩 점수를 합산할 뿐, 여전히 **처음 질문 하나(`q`)로 한 번만 검색**합니다.
- 하지만 사용자의 질문(`"지난주 A사 미팅 때 요청받은 자료"`, `"집들이 때 마신 화이트 와인"`)에는 최종 정답 문서에 들어 있는 **핵심 브릿지 단서(담당자 `민수`, 집들이 날짜 `3/15`, 정식 제품명 특징)**가 아예 빠져 있습니다.
- 따라서 BM25와 일반 임베딩을 아무리 합쳐도 **1차 검색에서 중간 단서(Hop 1)만 건지거나 표면적으로 비슷한 다른 날의 오답**만 건질 뿐, **Hop 1에서 찾은 단서를 넣어 두 번째 질문을 다시 쓰는(Query Rewriting) 멀티홉 루프** 없이는 절대 최종 정답(Hop 2)에 도달할 수 없습니다.

### 2.3 삼성 PDE(Personal Data Engine)와의 관계 정립 (결선 발표 핵심 방어 논리)
> [!IMPORTANT]
> **`삼성_현재기술_조사.md` 기반 필수 준수 사항**:
> - *"지식그래프(PDE)는 멀티홉을 못 한다"*거나 *"PDE는 카카오톡을 못 읽는다"*고 단정하면 **절대 안 됩니다** (RDFox는 Datalog 규칙 추론이 가능하며, One UI 버전에 따라 지원 앱 알림을 수집함).
> - 대신 **"역할의 상호보완(Complementary Architecture)"**으로 포지셔닝해야 임원진의 큰 공감을 얻습니다:
>   1. **PDE (지식그래프 계층)**: 사용자의 반복적인 선호도, 루틴, 예약 확인 메시지, 명시적 인물·일정 등 **정형화 가능한 핵심 사실(Structured Facts)을 정교하게 관리하는 기반 엔진**.
>   2. **Weave (추론형 멀티홉 검색 계층)**: PDE의 그래프 스키마에 미처 구조화되지 않은 **앱 전반의 비정형 원문 조각들(스쳐 지나간 카톡 대화 맥락, 회의 메모의 축약어, 사진 속 텍스트·라벨)**을 **질의 시점(Query-time)에 Reasoning Embedding으로 즉석에서 엮어내는 연결 엔진**.

## Part 3. 3대 핵심 UX 시나리오 고도화 및 PPT 애니메이션 완벽 대체 설계

사용자가 일상과 업무에서 가장 빈번하게 겪으면서도, **BM25(키워드)·일반 임베딩·단순 지식그래프(PDE)가 모두 실패하고 오직 Weave의 [Query Rewriting + Reasoning Embedding + Metadata Filter] 멀티홉 파이프라인만 성공하는** 3대 시나리오 고도화 설계안입니다.

현재 `a1_deck00.py`가 생성하는 **12장(23클릭) 표준 파이프라인 구조**(`00 사전 준비 [3장]` → `질문의 순간 [1장]` → `기존 검색 한계: BM25 vs 임베딩 [1장]` → `Weave 하이브리드 한눈에 [1장]` → `01 순간 감지 [1장]` → `02 질문 다시 쓰기 [1장]` → `03 연쇄 탐색 Hop 1 [1장]` → `03 연쇄 탐색 Hop 2 [1장]` → `03 탐색 완료 요약 [1장]` → `04 전달 [1장]`)에 **1:1로 즉시 대입 가능한 수준**으로 모든 텍스트·메타데이터·오답 함정(Hard Negatives)·클릭별 애니메이션을 설계했습니다.

### 시나리오 3 고도화: [UX 3] 먼저 건네는 기억 (면세점 갈색병 시나리오)

#### 1) 기존 시나리오(`c3.py`)의 문제점과 고도화 포인트
- **기존 문제점**:
  1. 아내가 `"동생이 갈색병 써 봤는데 좋대 / 면세점에서 사면 더 싸대"`라고 카톡을 보낸 날(`10/12 월`) 밤에 찍은 스크린샷이 `에스티 로더 어드밴스드 나이트 리페어 50ml` 단 한 장뿐이라, *"그냥 10월 12일 밤에 찍은 사진 가져오면 끝나는 것 아닌가?"*라는 반론이 가능했음.
  2. 캡처 카드에 제품명만 적혀 있어서 `"갈색병"`과 `"에스티 로더 나이트 리페어"`를 어떻게 소형 임베딩 모델이 연결했는지(단순 브랜드 별명 암기인지, 문맥 추론인지) 불분명했음.
- **고도화 해결책 (시간 필터 함정 추가 + 캡처 내 자연어 단서 보강)**:
  1. **멀티 시그널 컨텍스트 트리거 명확화 (01 순간 감지)**:
     - `현재 위치: 인천공항 제2터미널 면세 구역 (GPS)` + `삼성 월렛 탑승권: 15:20 싱가포르행` + `현재 열린 화면: 아내와의 카카오톡 채팅방 ("출장 잘 다녀와~" / "응, 지금 출국장 들어왔어!")`
     - 사용자가 아무 검색어를 치지 않아도, **입력창에 커서가 놓이는 순간** 키보드 왼쪽 위의 Weave 실타래 버튼이 보라색으로 반짝이며 선제안(`1` 배지)을 띄움.
  2. **Hop 1 (상황 기반 질문 생성 → 아내 카톡 단서 포착)**:
     - 질문: `"면세점에서 아내에게 사 갈 만한 것은?"`
     - **함정 오답**: 삼성노트 `면세점 살 것 메모 (10/31: 내 선크림, 세면도구)` → `[내 출장 준비물]`이라 제외.
     - **정답 단서**: 아내 카톡(`10/12 월 22:40`): *"여보, 동생이 그 유명한 갈색병 에센스 써 봤는데 피부결에 진짜 좋대! 나중에 면세점 갈 일 있으면 듀오 말고 단품으로 사다 줘~"*
     - 추출된 단서: **`date: "2026-10-12"`, `"갈색병 에센스 (단품)"`**
  3. **Hop 2 (같은 날 밤 캡처 2장 중 Reasoning Embedding으로 진짜 제품 특정!)**:
     - `date: "2026-10-12"` 메타데이터 필터로 그날 밤 아내가 이야기한 직후 찾아본 갤러리 스크린샷을 조회하면 **2장의 캡처**가 나옴 (단순 시간 필터만으로 풀리지 않도록 설계!):
       - **함정 캡처 (`10/12 23:05`, `shot_coupon`)**: `[신라면세점] 출국 전 필수! 화장품·향수 최대 15% 할인 쿠폰팩 안내` (`"면세점"`, `"화장품"` 키워드가 그대로 들어 있어 BM25/단순 임베딩이 1순위로 낚이는 오답!)
       - **정답 캡처 (`10/12 23:12`, `shot_ans`)**: 삼성 인터넷 뷰티 리뷰/상품 캡처 — **`"에스티 로더 어드밴스드 나이트 리페어 50ml / 밤사이 피부를 케어하는 베스트셀러 갈색 보틀 리페어 세럼 (면세 단품)"`**
     - **왜 이 설계가 완벽한가?**:
       - 첫째, 같은 날 밤(`10/12 23시경`)에 캡처가 2장 있으므로 **"단순히 카톡 직후 시각 사진 1장을 가져왔다"는 반론을 완벽히 차단**함.
       - 둘째, 캡처 화면 안에 상품명(`에스티 로더 어드밴스드 나이트 리페어 50ml`)과 함께 부제/리뷰 한 줄(`"베스트셀러 갈색 보틀 리페어 세럼"`)이 포함되어 있어, 모델이 외부 은어를 억지로 외운 게 아니라 **캡처 속 텍스트·시각 단서(`갈색 보틀 리페어 세럼` + 용량 `50ml`)와 카톡 단서(`갈색병 에센스 단품`)를 Reasoning Embedding으로 정교하게 매칭**했다고 설명할 수 있음!

### 4.1 왜 기존 텍스트가 "LLM(Claude)이 쓴 글"처럼 느껴지는가? (진단 및 레퍼런스 비교)

현재 덱(`Weave_결선_중간본.pptx`)의 텍스트와 발표자 노트를 전수 분석해 보면, Claude가 한국어 프레젠테이션 카피를 생성할 때 자주 보이는 **4가지 전형적인 어색함(LLM-isms)**이 반복됩니다. 이를 **삼성 갤럭시 언팩(Galaxy Unpacked) 한국어 키노트**, **애플 WWDC 한국어 자막/카피**, **토스(Toss) 프로덕트 카피라이팅(Simplicity 23/24)**의 원칙과 비교하면 차이가 명확해집니다.

| 유형 | 현재 덱의 Claude 투 (Before) | 왜 어색한가? (원인 진단) | 레퍼런스 원칙 (Samsung Unpacked / Toss / Apple KR) | 사람다운 발표 문체 (After) |
|---|---|---|---|---|
| **① 어색한 쉼표(`,`)와 체언/부사구 끊어치기** | - `"먼저, 집들이 날부터"`<br>- `"막힐 땐, 키보드의 실타래 버튼"`<br>- `"정확한 이름을, 출처와 함께"`<br>- `"모든 기록을 미리, 벡터와 메타데이터로"` | 영어의 `"First, from the housewarming date"`나 `"When stuck, the spool button"` 구조를 그대로 옮겨 **불필요한 쉼표**를 찍고 동사 없이 명사로 문장을 뚝 끊음. 한국어 화자는 한 호흡에 읽히는 구절에 쉼표를 찍지 않음. | **[Toss UX Writing & Apple KR 원칙]**<br>한 호흡에 읽히는 짧은 카피에는 쉼표를 빼고, **자연스러운 서술어(동사/형용사)**나 **대조 대구법**으로 리듬감을 만듦. | - `"첫 번째 단서, 집들이 날짜부터 찾습니다"`<br>- `"이름이 막힐 땐 키보드의 실타래 버튼"`<br>- `"정확한 제품명을 출처와 함께 건넵니다"`<br>- `"쌓이는 기록을 미리 의미 벡터와 메타데이터로"` |
| **② 유아적이거나 직역투인 기술 풀어서 쓰기** | - `"뜻을 숫자의 줄, 벡터로 바꿔 두고"`<br>- `"모르는 건 빈칸으로"`<br>- `"단서로 빠진 한 단계를 채웁니다"` | 전문 용어를 쉽게 풀려다 보니 `"숫자의 줄"` 같은 어색한 조어(Coined literal phrase)가 나왔고, `"빈칸"`, `"빠진 한 단계"`처럼 교과서 문제풀이 같은 표현이 사용됨. | **[Samsung Galaxy Unpacked 키노트 원칙]**<br>임원·대중 겸용 발표에서는 억지 조어 대신 **"의미를 담은 숫자(벡터)"**, **"끊어진 기억의 고리"**, **"비워 둔 단서 자리"**처럼 직관적이면서도 품격 있는 한국어를 사용함. | - `"기록의 맥락은 의미 벡터로 변환해 두고"`<br>- `"아직 모르는 단서는 빈칸으로 비워 둡니다"`<br>- `"Weave는 단서를 이어 끊어진 고리를 완성합니다"` |
| **③ 사물이 주어가 되는 비문·피동 표현** | - `"가까운 기록 몇 개가 나오는데, 선물 메모엔 날짜가 없고, 지은의 카톡이 이어집니다"`<br>- `"다시 쓴 질문이 이 캡처와 가까워집니다"` | `"카톡이 이어집니다"`, `"질문이 캡처와 가까워집니다"`는 한국어에서 매우 어색한 무생물 주어 구문임. 사람이 말할 때는 **"지은이와 나눈 카톡에서 단서를 찾습니다"**, **"그날 밤 찍어둔 캡처와 정확히 연결됩니다"**라고 표현함. | **[한국어 자연스러운 능동 화법 원칙]**<br>무생물 주어(`질문이 가까워진다`) 대신 **AI의 행동이나 사용자의 시선(`Weave가 ~를 찾아 연결합니다`)**을 중심으로 서술함. | - `"선물 메모에는 날짜가 없지만, 지은이와 나눈 카톡에서 결정적인 단서를 찾습니다"`<br>- `"완성된 질문이 그날 밤 찍어둔 상품 캡처와 정확히 맞닿습니다"` |
| **④ 번역투 명사 나열형 발표자 노트** | - `"핵심 가치: 찾는 시간 단축, 앱 전환 감소, 대화와 업무의 흐름 유지."`<br>- `"여러 앱에 파편화된 일상 데이터를 삼성의 PDE 기술을 이용해 통합 분석하여 개인화된 맞춤 경험을 제공합니다"` | 첫째 예시는 보고서 개조식 메모를 발표 대본에 그대로 넣은 것이고, 둘째 예시는 `~를 ~를 이용해 ~하여 ~를 제공합니다`라는 전형적인 번역투 복문임. | **[실전 발표 스크립트 원칙]**<br>발표자 노트는 눈으로 읽는 보고서가 아니라 **입으로 소리 내어 말할 때 호흡이 자연스러운 구어체(`~하죠`, `~합니다`)**여야 함. | - `"결국 찾는 시간과 앱을 오가는 번거로움은 줄이고, 대화와 업무의 흐름은 끊기지 않게 지켜줍니다."`<br>- `"여러 앱에 흩어진 일상 데이터를 삼성 PDE와 연계해 기기 안에서 안전하게 분석하고, 나에게 꼭 맞는 경험을 전합니다."` |
