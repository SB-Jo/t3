## 2. 왜 Reasoning Embedding인가

Weave가 받는 요청은 키워드 검색보다 불완전합니다. "지은이네 집들이 때 마신 와인"을 찾는 사용자는 제품명도 날짜도 모르고, 답이 담긴 사진에는 '지은'이나 '집들이'라는 글자가 없을 수 있습니다. 그래서 질문과 정답을 바로 비교하기보다, **답까지 이어 줄 중간 근거**(집들이 일정)를 찾는 능력이 중요합니다.

제안서에서 주장하는 범위는 다음과 같습니다.

- 주장함: **긴 추론 문장을 매번 생성하지 않고도, 현재 단서에서 다음 근거를 찾는 경량 검색 모델을 활용한다.**
- 주장하지 않음: Reasoning Embedding 하나가 캘린더를 열고, 날짜를 뽑고, 사진을 찾고, 라벨을 읽고, 답을 판정한다.

## 3. 역할 분담 — 임베딩 내부의 추론과 앱 사이의 연쇄 탐색을 구분

| 해야 하는 일 | 담당 | 장표 표시 |
| --- | --- | --- |
| '집들이'와 관련된 일정·대화 후보 찾기 | Reasoning Embedding + 키워드 검색 | ① 날짜 찾기 · **추론 검색** |
| 일정에서 날짜 가져오기 | 캘린더의 구조화된 필드 | 탐색 메모 '확인한 단서 3/15' |
| 그 날짜의 사진으로 범위 좁히기 | 시간 조건 필터 | ② 그 시간 사진 · **시간 필터** |
| 사진 속 와인 이름 읽기 | OCR | ③ 라벨 읽기 · **OCR** |
| 다음에 무엇을 찾을지, 언제 끝낼지 | 탐색 메모·Routing | 02 단서 정리 "다음에 무엇을 찾을지, 언제 멈출지" |
| 답장·검색어 구성 | 템플릿, 필요할 때만 sLLM | 04 전달 |

Reasoning Embedding의 가치는 세 가지입니다. 이름을 모르거나 표현이 달라도 관련 기록을 찾고, 지금 확보한 단서에 비춰 도움이 될 다음 기록을 고르고, 겉보기엔 비슷하지만 다른 사람·다른 행사의 기록을 가려냅니다. 반대로 날짜·출처처럼 정확히 알 수 있는 조건은 추론하지 않고 필터와 원문 연결로 확인합니다. 장표 연쇄 탐색 카드의 설명 "모호한 단서는 Reasoning Embedding이, 정확한 조건은 필터가 맡습니다"가 이 원칙입니다.

## 4. 동작 — 탐색 메모와 반복·종료

1. **Trigger:** 검색창·Weave 버튼은 바로 시작합니다. 대화·맥락 파악으로 먼저 건넬 때는 관련성·지금 쓸 수 있는지·최근 노출 여부를 한 번 더 확인합니다.
2. **Routing:** 탐색 메모에 **찾을 것 / 확인한 단서 / 아직 필요한 것**을 적습니다. 예: 와인 이름 / 지은·집들이(→ 3/15) / 그날 와인 사진. 요청이 복잡할 때만 sLLM이 제한된 형식(JSON)으로 메모를 채웁니다.
3. **Multi-hop Search:** 메모 상태로 다음 근거를 검색합니다. 모호한 단서는 Reasoning Embedding이 찾고, 확인된 날짜 같은 정확한 조건은 필터로 겁니다. 새로 확인한 단서는 메모에 채웁니다. 검색 결과를 질문 뒤에 계속 붙이면 같은 기록을 반복하거나 엉뚱한 방향으로 흐를 수 있어, 메모 상태를 기준으로 삼습니다.
4. **종료:** 필요한 정보가 채워지면 멈춥니다. 새 단서가 없거나 탐색 한도에 닿아도 멈춥니다. 후보가 여럿이면 확정하지 않고 사용자가 고르게 합니다.
5. **Delivery(전달):** 직접 검색에서는 후보를 출처와 함께 보여주고, 먼저 알리는 기억은 근거가 확실할 때만 표시합니다. 사용자가 고른 것만 입력합니다.

LLM 에이전트처럼 단계마다 추론 문장을 생성하는 방식은 지연·전력이 요청마다 크게 달라지고, 작은 모델이 없는 날짜·이름으로 검색할 위험이 있어 기본 경로에서 제외했습니다. 예외적으로 어려운 요청을 처리하는 보조 경로로는 둘 수 있습니다.

## 5. Weave 기술 포인트 (장표·노트에 가볍게 반영)

- **'정답과 비슷한 기록'뿐 아니라 '다음 단서를 주는 기록'을 찾는다.** 학습 데이터도 '질문 + 확인한 단서 → 다음으로 필요한 기록'과 헷갈리는 오답(다른 집들이, 다른 날짜, 같은 사람의 다른 약속)으로 구성합니다. 이 방식 자체는 기존 연구(MDR 등)와 연결되므로 세계 최초라고 주장하지 않습니다. 대신 개인 기록의 사람·시간·사건 관계에 맞게 적용하는 것을 Weave의 기술 전략으로 제시합니다.
- **정확히 알 수 있는 조건은 추론하지 않는다.** 날짜는 시간 필터, 출처는 원문 연결로 처리합니다. 온디바이스 효율과 신뢰성을 함께 설명할 수 있습니다.
- **충분히 찾았으면 멈추고, UX에 따라 다르게 건넨다.** 직접 검색은 후보를 보여주고, 먼저 알리는 기억은 더 확실한 근거가 있을 때만 알립니다.

## 7. 수정 방법

HTML(`pages/*.html`)이 원본입니다. 문구를 바꾼 뒤 `node tools/render.cjs pages/page-07-pipeline.html pages/page-15-qna.html pages/page-16-glossary.html`와 `python tools/build_pptx.py`를 실행하면 PNG·PPTX가 다시 만들어집니다. PPTX에서는 글자가 모두 편집 가능한 텍스트박스이고, 카드·칩·배지는 네이티브 도형입니다. PowerPoint 없이 LibreOffice로만 렌더를 확인했습니다.
