## 바뀐 것 (5차 피드백 → 반영)

| 피드백 | 반영 |
|---|---|
| '~에요' 남발은 LLM 같음. '폰'은 잘 안 쓰는 말 | 화면 설명은 짧은 어구, 끝맺음을 섞었다. '~요'는 "정답은 이미 어딘가에 있어요!" 한 줄뿐. '폰'은 뺐다 |

| 장이 너무 잘게 쪼개짐(mp4 기준 10~20% 줄이기) | 질문 나누기 + 빈칸, 빈칸 채우기 + 다시 쓴 질문을 한 장씩으로, 멈춤 장은 정리 장의 '멈춤' 알약으로, A1은 필터와 찾기를 한 장으로. 17~18장 → 13~14장 |
| C3 '아내의 언니', 결제 메일로 찾기가 어색함 | 아내 카톡 "여보, 동생이 갈색병 써 봤는데 좋대 / 면세점에서 사면 싸대~" → 9월에 아내가 보낸 쇼핑 링크 "이거 다들 쓰더라" + "에스티 로더 / 어드밴스드 나이트 리페어 50ml" |

리뷰어 지적으로 더 고친 것:
- C2의 "오타니가 LA 팀인 건 모름"은 과장이라(일반 임베딩도 대개 잇는다) 실패를 한 장으로 바꿨다. 한 번 검색은 '오타니 유니폼'까지만, 사이즈는 다른 카톡.
- 답 태그 "질문과 딴판"은 임베딩엔 사실이 아닐 때가 있어 "먼저 알아야 할 단서" 태그로 바꿨다.
- 다시 쓰기 노트에 "처음 질문엔 없던 X가 이제 질문에 들어 있다, 한 번 검색과 다른 점"을 넣었다. C3 노트의 "Reasoning Embedding은 별명을 안다"는 "갈색병은 흔한 별명이라 다시 쓴 질문이 링크와 가까워진다"로.
- A1 실패 부제 "사진엔 ‘화이트 와인’이란 글자가 없음", 임베딩 노트 "카톡엔 와인 얘기가 없어 순위가 밀림". C1 가족 단톡방 본문의 '엄마:'는 보낸 사람 표시로 뺐다. B2 첫 질문 "지난번 동창회, 결국 어디로 정했지?". C2 시각은 LA 오후 4시(한국 다음 날 오전 9시).
- 가까이 보는 장 설명은 칩과 겹치지 않게 이유만(예: "잡은 곳 = 예약한 곳", "오타니 = LA 다저스", "매장엔 ‘갈색병’ 대신 이 이름과 용량으로").
- 노트 말투: "요즘 검색은 보통 키워드 검색과 임베딩 검색을 함께 씁니다", "질문 다시 쓰기, Query Rewriting", "보내기는 직접 누릅니다".
- 마감: 답이 길면 '멈춤'이 아래 줄로 가고 질문 판이 그만큼 길어짐, 첨부 아이콘은 문서 모양, 통합 검색 시트가 클 때 이중 테두리 없앰, 와인 라벨 알약 불투명, 사진은 비율 맞춰 잘라 냄.

## 8차(2026-11-02 밤): 00이 맨 앞, 클릭마다 한 단계, 말투, 여백

덱 기본판은 `a1_deck00.py`(17장, 클릭 25번)이다. `a1_deck.py`(15장)와 `a1.py`(16장)도 같은 엔진으로 빌드된다.

| 요청 | 반영 |
|---|---|
| '~모름', '~채움' 같은 말투가 어색함. 어구나 ~요/~다 문장으로 | 설명과 태그를 모두 고침(-ㅁ/-음/-함/-기로 끝나는 말 없음). 예: "같은 단어를 찾는 / 키워드 검색", "Weave는 단서로 / 빠진 한 단계를 채웁니다", '와인 얘기가 없는 메모', '집들이 날인지 몰라요', 정리 장 '멈춤' → '탐색 끝'. 8·9쪽 배지와 작은 글("Hybrid 키워드 + 멀티홉 + 추론", "가장 가까운 뜻", "날짜는 지은 카톡에, 와인은 그날 사진에")은 뺐다 |
| 00은 모든 플로팅에, 맨 앞에. 지금은 HIW에 00이 없음 | 덱 기본판 = 00판. 1장 기록 더미 → 2장 모든 조각 아래 벡터 줄(클릭) → 날짜(클릭) → 3장 지은 카톡 하나를 가까이(조각 아래 벡터 줄이 판의 '벡터' 줄로 날아감) → 4장 질문의 순간. 위 띠는 처음부터 00~04 |
| 키워드·임베딩을 발표자가 차근차근 설명하게, 직관과 반대 순서인 애니메이션 점검 | 키워드 장: 판과 질문(전환과 함께) → 클릭: 질문 속 단어 형광펜 → 클릭: 같은 단어가 든 결과 → 클릭: 아닌 이유. 임베딩 장: 판과 질문 → 클릭: 질문 벡터(00과 같은 색 칸 줄) → 클릭: 저장해 둔 기록 벡터 다섯 줄 + 가까운 정도 막대 → 클릭: 가장 가까운 두 기록(테두리 + 1·2) → 클릭: 아닌 이유, 지은 카톡은 맨 아래(점선 + 태그). 그다음 두 판을 나란히. 모든 장에서 결과가 판보다 먼저 나오지 않게 했고, 효과는 0.2~0.3초 |
| 9쪽: 정보 밀도가 낮고 한 번에 뜸 | 질문과 사진 사이 '빠진 한 단계'(점선 + ?)에서 시작 → 클릭: 지은 카톡 + 추론('단어가 달라도 같은 일') → 클릭: 단서 칩 + 멀티홉('찾은 날짜로 다음 질문') → 클릭: 날짜 형광펜 + 키워드('날짜가 딱 맞는 사진') + 답 |
| 7쪽 여백 | 흩어진 조각이 화면 왼·오른쪽에서 32px, 아래에서 44px(1280 기준) 더 떨어지게 |

장 안 효과: `step.anim`은 장이 열리자마자(짧게), `step.beats`는 클릭마다. 노트의 '(클릭)' 표시 수가 장마다 클릭 수와 같다(빌드 때 확인). 미리보기 영상은 클릭을 2초 간격으로 저절로 넘긴 영상용 사본을 녹화한 것이다.

## 7차(2026-11-02): 실패 한 장으로 묶기, Weave 하이브리드 장, 00판, 삼성 글꼴

A1(과 덱용 A1)에만 반영했다. 다른 판은 예전 실패 장 그대로다.

| 요청 | 반영 |
|---|---|
| 키워드 검색은 왼쪽, 임베딩 검색은 오른쪽에 묶어 '둘 다 안 됨'으로. 임베딩은 '가장 가까운 것'이 보이게(형광펜처럼) | 실패 두 장 → 한 장(`fail` mode `'pair'`). 왼쪽은 BM25 판 + 같은 단어 형광펜 + 결과 둘. 오른쪽은 임베딩 판 아래 '임베딩 공간': 질문이 별 모양 점 하나가 되고, 점선 원 안의 가장 가까운 사진 둘이 1·2위(다른 날 와인, 어느 날인지 모름). 날짜가 든 지은 카톡은 원 밖 먼 곳에 점선 테두리 + '날짜는 여기, 와인 얘기는 없음'. 구분선으로 두 판을 나란히. "둘을 합쳐도(하이브리드도) 안 됨"은 장과 노트에서 모두 뺐다(하이브리드는 이제 Weave의 이름) |
| 그다음 우리 해결: Hybrid(키워드 + 멀티홉 + 추론), 단서를 잡아 중간 단계를 채움 | 새 장 `hybrid`. 질문 → 지은 카톡(중간 단서, '이사 기념' 형광펜, 이름표 '추론') → 단서 칩 '3/15 (일) 저녁'(이름표 '멀티홉') → 그날 사진(날짜 형광펜, 이름표 '키워드') → 답 '배비치 소비뇽 블랑'. 설명 "Weave는 단서를 잡아 / 중간 단계를 채움", 알약 "Hybrid  키워드 + 멀티홉 + 추론". 덱 부록 Q&A 28쪽(중간본 기준, 정확한 이름은 키워드 색인, 표현이 다른 내용은 벡터 색인)과 맞춤 |
| 00을 다시 넣는다면 플로팅이 벡터 + 메타데이터로 저장되는 그림 | `a1_deck00.py`(15장). 더미 다음 두 장: ① 지은 카톡 조각이 카드로 커지고 오른쪽 '기기 안에 저장한 모습'에 글자(옅게) · 벡터(색 칸 16개, Jay Alammar 단어 임베딩 그림을 보라 한 색으로) · 메타데이터 칩(날짜, 카카오톡, 보낸 사람) ② 떠 있던 조각이 '기기 안 저장소'로 날아 들어감(이야기 기록 여섯은 아이콘 + 이름 + 작은 벡터 + 날짜 한 줄씩, 나머지는 같은 모양의 묶음). 위 띠는 00~04(00 '사전 준비'), 00 다음 장부터 ✓. 두 번째 홉 설명은 "저장해 둔 날짜로 거르고, / 그날 사진 중에서" |
| 덱 글꼴을 SamsungOne으로 | `hiw_lib.SAMSUNG = True`: 글자 폭을 SamsungOneKorean(06_에셋/글꼴, 400·500·700)으로 잼(형광펜·칩 폭이 실제 글자와 맞게). `build5.render`가 저장 직전에 `11_중간본/samsung_fonts.remap_prs`를 불러 Inter·Noto Sans KR을 SamsungOneKorean으로 바꿈 |

장 구성: A1 14장(open, cloud, fail_pair, hybrid, trig, split, find1, close1, rw2, find2, close2, deliver, result, sum), 덱용 A1 13장(result 뺌), 덱용 00판 15장(덱용 + idx1, idx2).
