## 낭독(TTS)

미리보기 영상의 목소리는 이 컴퓨터 안에서 만들어요(`tts_c.py`, `tts_worker.py`). 대본을 밖으로 보내지 않아요.

- 목소리는 Supertonic 3(Supertone이 공개한 온디바이스 음성 합성, ONNX, CPU)의 F3예요. 아나운서 말씨로 소개된 목소리이고, 모델 기본 속도(1.05) 그대로가 발표 속도와 가장 가까워요. `--voice M1`처럼 바꿀 수 있어요(F1~F5, M1~M5. 목소리마다 말 빠르기가 달라서 `tts_c.SPEEDS`에 속도를 따로 줄 수 있음). `--voice heami`는 Windows에 깔린 한국어 음성(Microsoft Heami)이고, Supertonic 환경이 없으면 저절로 이걸 써요.
- (클릭)마다 토막 내어 읽혀요. 문장 중간에서 끊는 토막은 끝에 쉼표를 붙여 말끝이 내려가지 않게 해요. 영문과 숫자는 읽는 소리로 바꿔 넘겨요(Weave → 위브, UX → 유엑스, 3월 15일 → 삼월 십오일).
- 같은 글은 늘 같은 소리가 나오고(난수 씨앗을 글에서 뽑음), 한 번 만든 토막은 `out/tts_cache`에 남겨 다시 만들지 않아요.
- PowerPoint 녹화는 계산한 때와 조금씩 어긋나요(끝에서 1.3초 늦음). 그래서 자막마다 왼쪽 아래 구석에 작은 표를 함께 띄우고, 녹화에서 그 표가 바뀌는 때를 읽어 낭독을 그 자리에 놓아요. 표는 낭독을 얹으면서 바로 위 바탕으로 덮어 지워요(영상을 다시 인코딩). 소리 크기는 -16 LUFS에 맞춰요. 소리 없는 녹화는 `out/_silent.mp4`에 남고, `--remux`를 붙이면 녹화는 그대로 두고 낭독만 다시 얹어요.
- `--check`는 낭독을 받아쓰기(faster-whisper large-v3-turbo, 기기 안)로 다시 글로 바꿔 노트와 견줘요. 17장 모두 노트대로 들렸어요(받아쓴 글은 `out/tts_check.txt`). 완성한 영상의 소리도 장마다 잘라 같은 방법으로 견줬고, 자막이 바뀌는 때와 말이 시작하는 때가 44구간 모두 0.1초쯤 차이로 맞았어요.

## 솔루션 세 장은 조각으로 만들어요

`page-05-solution_claude.html`의 요소를 `data-l="ux1/phone"`처럼 조각으로 묶었어요. `export_layers_claude.cjs`가 조각마다 투명 PNG(3배 화소, 그림자까지)로 찍고, `build.py`가 조각 하나를 PowerPoint 묶음 하나(그림 + 글상자)로 넣어요. 그래서 조각마다 따로 움직이고, 세 장 사이에서는 이름이 같은 조각끼리 모핑으로 이어져요. 번호와 이름(① 기록 통합 검색 …)은 `build.py`가 덱 글꼴로 폭을 재서 묶음의 가운데 위에 그려요(HTML의 이름표는 미리보기용).

## 'Hybrid Index'라는 말

- 널리 쓰는 말은 Hybrid Search예요. 키워드 검색과 벡터 검색을 한 번의 요청으로 함께 쓰는 검색을 가리켜요. Microsoft는 "plain-text content와 embeddings를 함께 담은 search index에서 full-text와 vector 질의를 한 요청으로 돌린다"고 설명하고, 필터는 별도 구조에서 적용돼요([Azure AI Search, Hybrid search overview](https://learn.microsoft.com/en-us/azure/search/hybrid-search-overview)).
- 그 검색을 받치는 색인을 hybrid index라고 부른 것은 Pinecone이에요. 2022-10-31 글 제목이 "Introducing the hybrid index to enable keyword-aware semantic search"이고, dense와 sparse 표현을 한 색인에 담는다고 썼어요. Pinecone의 지금 문서는 "Hybrid search combines a keyword signal with a semantic signal"로 설명해요([Pinecone, Hybrid search](https://docs.pinecone.io/guides/search/hybrid-search)).
- 12쪽 카드는 원문(키워드), 의미 벡터, 메타데이터(필터)를 한 색인에 두는 그림이라 이 뜻과 맞아요. 그래서 이름은 그대로 뒀어요.

## PowerPoint에서 배운 것

- 닦아 내기 필터 이름은 보이는 방향과 반대예요. `wipe(up)`은 위에서 아래로, `wipe(down)`은 아래에서 위로 드러나요. `motion.py`의 `WIPE`가 `dir='down'`(아래로 나아감)을 `wipe(up)`으로 바꿔 적어요.
- `slide(fromBottom)` 필터는 아래에서 밀려 올라오지 않고 위에서 펼쳐지듯 나와요. 1쪽 검색 시트는 이동 경로(70px 아래 → 제자리)와 페이드로 올려요.
- 이동 경로의 시작점은 놓인 자리가 아니어도 돼요(`M`이 시작 자리). 그래서 '다른 자리에서 나타나 움직이기'를 경로 하나로 할 수 있어요. 장표 밖에 둔 조각(temp)이 날아오는 것도 순간 이동 없이 경로 하나로 해요(2쪽·17쪽의 칩, 15쪽의 주황 별).
- 처음 효과가 이동 경로인 도형은 처음부터 보여요. 숨겨 두려면 나타나는 효과를 먼저 적어요(`s_sol1`의 `enter`, temp 조각의 `type`·`wipe_in` 다음 `jump`). 나중에 나타나는 조각을 앞선 이동 묶음에 넣으면 안 돼요.
- 깜빡이는 커서(끝없이 되풀이)는 사라지는 효과로 지워지지 않아요. 2쪽의 옛 커서는 이동 경로로 장표 밖에 내보내요.
- 점 둘짜리 실은 그려지지 않아요(`hiw_lib.curve`는 점 넷이 한 마디). 곧은 실은 `[a, a, b, b]`로 줘요. 9쪽의 질문 → 벡터 실과 19쪽의 01 → 02 화살표가 그래서 보이지 않았어요.
