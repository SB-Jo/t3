## 0. 한눈에

1. 포커스는 움직임보다 **불투명도**로 만든다: 베일(나머지를 흐리게) + 베일 위 복제 카드. 확대·카메라 느낌은 장면이 바뀔 때 두 번만.
2. **클릭 1번 = 바뀌는 의미 1개**, 클릭당 애니메이션 합계 1.2초 이내, 클릭 사이 화면은 정지.
3. 숫자는 인트로와 맞춘다: 흐림 0.28–0.38, 포커스 1.07배, 형광펜 0.5초, 실 0.55초, 토큰 0.7초, 카메라 0.9–1.0초.
4. 보라는 Weave가 한 일에만. 기존 방식의 실패는 회색 점선·회색 형광펜·짧은 태그(빨강·노랑 없음).
5. "와!"는 마지막 클릭에 몰아 준다: 베일이 걷히며 실 3가닥 + 메모 + 답 + 출처가 한 화면에, 그 뒤 3초 이상 정지.

## 1. 레퍼런스 10

**R1. Zongker & Salesin, *On Creating Animated Presentations* (Eurographics/SIGGRAPH SCA 2003)**
- 무엇: 애니메이션 발표 도구(Slithy)를 만들고 실제 학회 발표에 쓰며 정리한 '발표용 애니메이션 원칙'(4장). 이번 과제와 가장 가까운 1차 자료.
- 가져올 것: ① "Do one thing at a time" — 여러 개가 함께 바뀌면 어디에도 집중 못 함, 복잡한 도식은 천천히·자주 멈추며 말과 맞춤 ② 순간 전환 대신 최소한 크로스페이드 ③ 주목 신호(색 변화·화살표)는 실제 동작과 헷갈리지 않게 ④ 같은 섹션은 잔잔하게, 새 섹션으로 넘어갈 때만 큰 효과 — 잔잔한 전환이 큰 효과의 힘을 키움 ⑤ 줌으로 디테일을 키웠다 줄이면 맥락이 유지됨 ⑥ dynamics(과정 자체)와 transitions(주목·전환)를 구분.
- 이 장표: 토큰·실 = 검색이 실제로 하는 일(dynamics), 베일·복제 카드 = 주목(transitions). 큰 움직임은 'Weave 시작'과 '답 공개' 두 번.
- https://www.cs.ubc.ca/~van/cpsc590/papers/Zongker.pdf

**R2. Heer & Robertson, *Animated Transitions in Statistical Data Graphics* (IEEE InfoVis 2007)**
- 무엇: 전환 애니메이션 설계 지침 + 실험(애니메이션 전환이 변화 추적을 유의하게 개선).
- 가져올 것: 복잡한 전환은 단순한 단계로 쪼개기(staging) / 동시에 여러 변화·예측 안 되는 경로는 인지 부담 / slow-in slow-out / 가림 최소화 / 같은 의미는 같은 전환, 다른 의미는 확실히 다른 전환 / 길이는 "as long as needed, but no longer" — 약 1초 권장(움직임이 작으면 더 짧게), 실험은 1.25초 / 이동·확대축소가 회전보다 이해 쉬움.
- 이 장표: 홉 하나를 '형광펜 → 실+토큰 → 다음 카드'로 쪼갬. 실패 3종은 같은 회색 문법, Weave는 보라 문법. 회전 없음.
- https://idl.uw.edu/papers/animated-transitions · PDF 3.2절 https://homes.cs.washington.edu/~jheer/files/2007-AnimatedTrans-InfoVis.pdf

**R3. Tversky, Morrison & Bétrancourt, *Animation: Can It Facilitate?* (Int. J. Human-Computer Studies, 2002)**
- 무엇: "애니메이션이 정적 그림보다 낫다"는 근거가 약하다는 리뷰.
- 가져올 것: 애니메이션은 "too complex or too fast to be accurately perceived"인 경우가 많고, 사람은 연속 과정도 "sequences of discrete steps"로 이해하며, 조절(interactivity)을 잘 쓰면 두 문제가 줄어든다.
- 이 장표: 연속 영상보다 발표자가 속도를 쥐는 클릭 빌드가 맞다. 클릭마다 '완결된 정지 화면'이 남아야 한다.
- https://digitalcommons.bryant.edu/apwork/1 (초록)

**R4. Mayer 멀티미디어 학습 원칙 (Mayer 2009 요약, Dartmouth)**
- 가져올 것: 신호(중요한 것만 색·대비로) / 분절(듣는 사람 속도의 짧은 조각) / 일관성(군더더기 제거) / 시간 근접(말하는 순간 그 그림) / 공간 근접(라벨은 대상 옆) / 중복(그림+말이면 같은 문장을 화면에 또 쓰지 않음) / 사전 훈련(핵심 개념 먼저).
- 이 장표: 형광펜 = 신호, 클릭 = 분절, 설명 문장은 말로만, 방법 이름은 실·메모 옆. Weave 첫 클릭에 '검색 메모'를 먼저 보여 주는 것 = 사전 훈련.
- https://services.dartmouth.edu/TDClient/1806/Portal/KB/PrintArticle?ID=171655

**R5. Nancy Duarte(*slide:ology*, Glance Test) + Garr Reynolds(Signal-to-Noise)**
- 가져올 것: "Instead of snapping from slide to slide, pan through a scene"(p.192), 요소를 등장인물처럼 들이고 내보내기(p.198), "Animation should tell a story"(p.184). Glance Test: 요점이 3초 안에 읽혀야 함. Reynolds: 소음 = "dense text, redundant bullet points, distracting animations, or irrelevant visuals".
- 이 장표: 벽은 그대로 두고 '조명'만 옮기는 한 장면 구성. 끝 화면은 3초 안에 "질문 → 세 번 건너 → 답"이 읽혀야 함.
- https://diagrammer.duarte.com/book/slideology/ · https://www.duarte.com/resources/slide-glance-test/ · https://presentationzen.com/blog/the-signal-to-noise-ratio-activity

**R6. 모션 수치 — NN/g + Material 모션 토큰**
- NN/g(Laubheimer 2020): 대부분 100–500ms, 큰 화면 변화 200–300ms, 400ms는 큰 화면의 큰 이동용, "At 500ms … a real drag", 등장이 퇴장보다 약간 길게(300 vs 200–250ms), 기본은 ease-out, 너무 긴 경우가 훨씬 흔함.
- Material(MDC-Android Motion.md): 등장 decelerate·퇴장 accelerate, emphasized decelerate = cubic-bezier(0.05, 0.7, 0.1, 1), 길이 토큰 50–1000ms(이동 거리·면적이 클수록 길게), 스프링은 spatial(위치)과 effects(색·불투명도, 오버슈트 없음)로 구분. MDC 텍스트 불투명도 high 0.87 · disabled 0.38.
- 이 장표: 발표 화면은 멀리서 보고 말과 맞추므로 작은 변화 0.25–0.5초, 큰 이동 0.9–1.0초(R2의 약 1초). 불투명도 변화엔 튕김 없음. 흐린 카드 0.28–0.38.
- https://www.nngroup.com/articles/animation-duration/ · https://github.com/material-components/material-components-android/blob/master/docs/theming/Motion.md · https://github.com/material-components/material-components-web/blob/0bfb393407727b9ad5e8de1e8dda6ea6a0ee21fd/packages/mdc-theme/README.md
- m3.material.io(Expressive 포함)는 스크립트로 그려져 본문을 못 읽어, 같은 토큰을 담은 MDC 문서로 대신함.

## 3. 클릭 빌드 규칙 14

1. **클릭 1번 = 의미 1개.** 한 클릭 안의 효과 2–4개는 '이전 효과와 함께/다음에'로 묶어 한 문장처럼 읽히게(예: 실이 그려지며 토큰이 건너감). 의미가 둘이면 클릭도 둘. — R1, R2 staging, R4 분절
2. **클릭당 합계 ≤ 1.2초 (판단).** 효과 하나는 0.25–0.6초, 벽 전체 이동만 0.9–1.0초. 발표자가 애니메이션을 기다리는 순간이 없게. — R6(500ms부터 느리게 느껴짐), R2(큰 전환 약 1초), R7
3. **들어올 땐 감속·조금 길게, 나갈 땐 가속·짧게.** 등장 0.4–0.5초, 퇴장 0.25–0.3초. 이동 경로는 부드럽게 시작·종료 각 30–50%(인트로 power2/3.inOut과 비슷, 판단). Bounce end·오버슈트 금지. — R6, R2, R8, R7
4. **베일 = 나머지가 28–38%만 보이게.** 슬라이드 크기 사각형, 배경색 #FBFAFF, 투명도 28–35%(투명도 값 ≈ 아래가 보이는 비율). 인트로 0.28과 Material disabled 0.38 사이. 프로젝터에서 벽이 사라져 보이면 35–40%로. Fade 0.45초. — 인트로, R6
5. **'앞으로'는 베일 위 복제 카드로.** 겹침 순서는 애니메이션으로 바꿀 수 없으니 포커스될 카드는 베일 위 레이어에 107% 크기 + 보라 링 + 그림자 한 단계 진하게 미리 그려 두고 Fade 0.45초. 확대 애니메이션 없이 '카메라가 다가간' 느낌, 글자도 선명. — 인트로, R7
6. **움직임 예산 (판단).** 한 클릭에 자리를 옮기는 것은 하나(토큰 또는 카메라). 토큰 이동은 화면 폭 1/3 이내. 벽 전체 확대·이동은 장 전체에서 최대 2번(Weave 시작, 답 공개), 1.15배 안팎·최대 1.3배. 회전·3D 기울기·블러 전환 없음. — R1, R7, R2
7. **시선은 왼→오 한 방향.** 질문 바(왼쪽 위) → 기록 벽(가운데) → 검색 메모(오른쪽 위) → 답(오른쪽 아래). 홉 3번도 왼→오로 놓아 토큰은 오른쪽으로만. 방법 이름·태그는 해당 실·카드 바로 옆. — R4 공간 근접, R5
8. **줌 느낌 vs 페이드.** 같은 장면 안의 포커스 이동은 Fade(베일·복제 카드), 선·형광펜은 Wipe. 줌 느낌은 ① 장면 경계(기존 방식 → Weave, 답 공개) ② 작은 글자를 읽혀야 할 때(사진 라벨 돋보기)만. — R1, R7
9. **멈춤과 말.** 모든 효과는 클릭에 묶고 자동 넘김 없음. 클릭 사이엔 반복·맥동·반짝임 없음. 클릭마다 말 1–2문장(5–8초, 판단) 동안 화면 정지, 애니메이션은 그 문장을 말하는 순간에. 클릭당 새 글자는 태그나 메모 한 줄까지. — R1, R4 시간 근접·중복, R7
10. **실패 3종: 같은 회색 문법, 결과만 다르게.** 방식 칩(회색) → 걸린 단어에 회색 형광펜·걸린 카드에 회색 점선 → 태그 1줄("단어만 같음" / "그런 관계 없음" / "비슷하지만 다른 날"). 클릭당 0.8초 이내. 빨강 X·경고 삼각형 없이 회색(#8E88A0 계열) 한 가지. — R2, R4 신호
11. **Weave는 확실히 다른 문법.** 보라 실·토큰·보라 형광펜·메모 줄은 Weave에만. 실패 표시와 같은 모양(점선·회색)을 쓰지 않는다. — R2(다른 의미 = 다른 전환), R1(dynamics/transitions 구분)
12. **홉 하나 = 3박자 ≤ 1.2초.** ① 0초: 지금 기록의 단서 단어에 형광펜 0.5초 → ② 0.3초: 실 Wipe 0.6초 + 토큰 경로 0.6초 동시 시작 → ③ 0.75초: 다음 기록 복제 카드 Fade 0.45초, 0.9초: 메모에 단서 한 줄 Fade 0.3초(방법 이름은 작게: 추론 검색 / 시간 필터 / OCR+추론). 토큰이 실 끝을 따라가게 시작·길이를 같게 하고, 토큰 경로의 부드럽게 시작·종료는 0에서 시작해 맞추기(실기). — R8, R10, 인트로
13. **멈춤은 거의 움직이지 않는 클릭.** 메모에 "답 찾음 → 멈춤" 체크 하나(Fade 0.3초), 남은 기록은 흐린 채. 마지막 공개 전 숨 고르기. — R10 종료 조건
14. **답 = 줌아웃 + 출처.** 베일 Fade out 0.6초(전체 사슬이 드러나는 줌아웃 느낌, 모핑을 쓰면 벽 1.0배 복귀) → 답 카드 떠오르기 0.5초 → 출처 칩 3개 Fade 0.3초(0.1초 간격), 칩마다 원래 기록과 얇은 보라 실. 와인 이름에만 굵게 + 형광펜, 글로는 답 카드에 한 번(0.45초, 반복 없음). 그 뒤 3초 이상 정지. — R1, R5, R9

## 4. 'LLM이 만든 티'·싸 보이는 패턴과 피하는 법

- **아이콘·이모지 남발**(카드마다 장식 아이콘, ✨·🔍) → 출처 표시는 실제 앱 아이콘 1개, 장식 아이콘 0. (Linear: 아이콘 수·크기 축소)
- **모두 빛남**(카드마다 글로·그라데이션 테두리) → 글로는 '지금' 한 곳. 지난 포커스는 얇은 링만 남기거나 지움. (Linear: 모든 요소가 같은 무게면 안 됨)
- **아무 데나 그라데이션**(보라→파랑 배경·버튼·글자) → 그라데이션은 실 하나(#A67CF2→#7B4BD8)에만. 배경 단색 #FBFAFF, 카드 흰색.
- **불릿·설명 문장**("1. 질의 분석 2. 검색 3. 생성") → 화면엔 기록·실·메모만, 설명은 말로. 화면 글자는 이름·날짜·숫자 위주. (R4, R5 Reynolds)
- **똑같은 카드 격자** → 기록 종류별 실제 모양(말풍선·사진·캘린더 칸·메일 제목줄·메모 첫 줄)과 실제 같은 디테일(보낸 사람, 20:14), 크기 2–3종.
- **효과 종류 남발**(날아오기·회전·튕김) → Fade·Wipe·이동 경로·떠오르기 + 돋보기 1곳 Zoom, 이 다섯만. (R1: "look at what my software can do", R8 Basic·Subtle)
- **클릭마다 모든 게 들썩임**(R1의 "tap-dancing" 불릿) → 바뀌는 것만 움직이고 벽·질문 바는 정지.
- **과장 카피**("혁신적인 AI가 모든 기억을 완벽하게") → 동사 3개와 결과: "찾고 → 좁히고 → 읽는다". (R9)
- **반복 맥동·파티클·반짝이** → 반복 0회, 강조는 한 번. (R7)
- **진한 그림자·두꺼운 테두리·구분선** → 그림자 1단계(포커스만 2단계), 테두리·구분선 최소. (Linear)
- **빨간 X·경고 아이콘으로 실패 표현** → 회색 점선 + 태그 1줄. (규칙 10)
- **가운데 정렬 제목 + 부제 + 3열 박스 템플릿** → 질문 바 하나가 제목 역할, 왼쪽 정렬로 시선 시작점 고정.

## 5. PowerPoint for Windows — 효과 신뢰도와 함정

| 효과(한글 UI) | 신뢰도 | 이 장표 용도 | 주의 |
|---|---|---|---|
| Fade(밝기 변화) 나타내기/끝내기 | 높음(웹 포함 전 버전) | 베일, 복제 카드, 태그, 메모 줄 | 기본값. 큰 요소를 '애니메이션 후 숨기기'로 순간 삭제하지 말고 Fade 0.25–0.3초로 퇴장 (R1) |
| Wipe(닦아내기) | 높음 | 실, 형광펜, 회색 점선 관계선 | 방향은 위·아래·왼·오른쪽뿐 → 실은 x방향으로 되돌아가지 않는 S자로 |
| 이동 경로(사용자 지정 경로) | 높음 | 토큰, (선택) 카메라 | 부드럽게 시작·종료 값 확인(실기). 끝점은 '점 편집'으로 단서 위치에. 경로를 '잠김'으로 두면 개체를 옮겨도 경로 고정 |
| Grow/Shrink(크게/작게) | 중간 | 쓰지 않거나 105% 이하 | 중심 기준으로 커짐. 사진을 100% 넘게 키우면 흐려진다는 실무 보고 → 최종 크기 복제본을 Fade로 |
| Transparency(투명) 강조 | 중간 | 개별 카드 흐리기(대안) | 개체마다 걸고 되돌리는 효과도 따로 필요, 지속 시간 옵션(다음 클릭까지 등)은 실기 → 베일 1장이 단순 |
| Zoom(확대/축소) 나타내기 | 중간 | 사진 라벨 돋보기 1곳 | "zooms into view from a distance" — 여러 곳에 쓰면 싸 보임 |
| Float In(떠오르기) | 높음(실기: 이동 거리·기본 시간) | 메모 카드, 답 카드 | 인트로의 '아래에서 올라오며 나타남'과 가장 비슷 |
| 모핑(전환) | 버전 의존 | 진짜 카메라 줌·팬(선택) | M365·2019·2021에서 만들기·재생, 2016은 재생만(업데이트 없으면 Fade로 재생). 1장을 여러 장으로 나눠야 함, !! 이름 1:1, 차트는 크로스페이드 |

- Grow/Shrink 흐림 보고: https://www.presentation-process.com/powerpoint-photo-animation.html · https://thepowerpointblog.com/2006/06/03/ (사진 기준, 도형·글자는 실기)
- **겹침 순서는 애니메이션으로 못 바꾼다**(효과 목록에 해당 효과 없음) → 레이어를 처음부터: 배경 → 기록 벽 → 베일 → 복제 카드·실·토큰 → 질문 바·메모·답.
- **그룹**: 애니메이션은 그룹 구조를 확정한 뒤에 건다. 그룹을 풀거나 다시 묶으면 걸어 둔 애니메이션이 사라지거나 바뀔 수 있음(실기). 그룹에 건 확대·경로는 그룹 중심 기준.
- **클릭 묶음**: 클릭마다 첫 효과만 '클릭할 때', 나머지는 '이전 효과와 함께'(+지연)·'이전 효과 다음에'. 애니메이션 창에서 클릭 번호가 1–9로만 보이는지 확인.
- **이름·통일**: 선택 창에서 `C05_캘린더_복제`, `C05_토큰`처럼 클릭 번호를 붙이면 애니메이션 창 정리와 모핑 !! 이름에 같이 쓸 수 있다. 같은 종류 효과의 길이는 애니메이션 복사로 맞춘다.
- **성능**: 글로·부드러운 가장자리·큰 그림자 개체를 여러 개 동시에 페이드하면 저사양 PC에서 끊길 수 있음(판단) → 발표 PC·프로젝터로 전체 리허설, 베일 투명도도 그때 확정.
- **모핑을 쓴다면**: 장면 A(클릭 0–3) → B(4–8, 벽만 1.1–1.15배) → C(9, 1.0배 줌아웃), B·C 진입 모핑 0.9–1.0초, 각 장 첫 효과를 '이전 효과 다음에'로 두면 클릭 1번에 카메라+베일이 함께 나옴. 앞 장의 애니메이션 끝 상태와 다음 장의 시작 상태를 똑같이 맞출 것(실기).
