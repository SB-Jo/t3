# 00 단계 레퍼런스: "개인 기록은 임베딩 벡터와 메타데이터로 저장된다"

작성 2026-11-02. 대상은 How it Works 앞의 00(전처리) 단계다. 흩어진 개인 기록(카카오톡 메시지, 사진, 메일 등)이 하나씩 기기 안에 "임베딩 벡터 + 메타데이터(날짜, 앱, 보낸 사람)"로 저장되는 장면을, 연라벤더 배경과 보라(#6B4EFF 계열) 강조, Morph 카메라 이동 스타일로 보여 주기 위한 시각 레퍼런스를 모았다.

## 0. 한눈에

**바로 빌려 쓸 시각 문법 세 가지**
1. **색 칸 띠**(Jay Alammar): 벡터를 숫자 대신 색 칸 한 줄로 그린다. 여러 줄을 쌓으면 비슷한 기록끼리 같은 열의 색이 겹친다.
2. **카드와 칩**(Apple Embedding Atlas): 기록 카드는 제목, 작은 출처 줄, 태그 칩으로 이루어지고, 옆에 임베딩 지도가 붙는다.
3. **줄 쌓기와 필터**(Pinecone): 기록 하나가 가로줄 하나가 되고, 메타데이터 질의가 그 줄들을 거른다.

**"기기 안 의미 색인"이라는 표현의 근거**
- Apple: WWDC24에서 "on-device semantic index"라고 표현했다.
- Microsoft Recall: "semantic index converts images and text into vectors"라고 설명하고, 메타데이터를 담는 스냅샷 저장소를 따로 둔다.
- Google Pixel Screenshots: 기기 안에서 처리하고 "어느 앱이나 웹사이트에서 왔는지" 같은 메타데이터를 남긴다.
- Android ML Kit + AppSearch: 문서 하나가 text, imageUri, embedding으로 구성된다.

**KG 주의**: 삼성 Personal Data Engine(PDE)은 RDFox 지식 그래프 기반이다. [확인] 개념을 빌리지 않고, 화면에 노드와 링크 선을 쓰지 않는다.

**추천 스토리보드(2장)**
- 00-1 "기록 하나가 두 갈래로": 카드 하나가 벡터 띠와 단서 칩으로 나뉜다.
- 00-2 "모든 기록이 한 줄씩": 모든 기록이 줄이 되어 기기 안 색인에 쌓인다.

### B1. Jay Alammar, "The Illustrated Word2vec" (2019-03-27)

- URL: https://jalammar.github.io/illustrated-word2vec/

- URL: https://www.pinecone.io/learn/vector-database/
- **생김새** [확인: 본문과 그림 2장을 직접 봄]
  - 손그림 흐름도: Content → Embedding Model(마름모) → "Vector Embedding [0.34, -1.2, …]" 상자 → 파란 "Vector Database" 패널. 패널 안의 점들 중 빗금 원 안에 있는 것이 가까운 이웃이고, 결과가 Query Result로 돌아간다.

### B4. Qdrant의 Point와 Payload (같은 패턴: Weaviate, Chroma)

- URL
  - Qdrant: https://qdrant.tech/documentation/manage-data/points/ , https://qdrant.tech/documentation/manage-data/payload/
  - Weaviate: https://docs.weaviate.io/weaviate/concepts/data
  - Chroma: https://docs.trychroma.com/docs/collections/add-data
- **생김새** [확인]
  - Qdrant: "A point is a record consisting of a vector and an optional payload." 예시는 `{"id": 129, "vector": [0.1, 0.2, 0.3, 0.4], "payload": {"color": "red"}}`이다. payload로 거를 수 있는 타입은 keyword, integer, float, bool, geo, datetime, uuid다.
  - Weaviate: 객체는 collection(class), properties, vector, UUID로 이루어진다("Objects normally include a vector that is derived from a machine learning model").
  - Chroma: `.add(ids, documents, embeddings, metadatas)` 형태로 넣는다.
  - 세 문서 모두 그림은 거의 없고 코드와 JSON 위주다.
- **가져올 것**: 레코드 한 줄 = id + vector + payload(키-값)라는 구성. 덱 라벨 체계의 근거가 된다.
- **적용 한 줄**: 00-1의 분해 장면에서 카드가 [벡터 띠]와 {날짜, 앱, 보낸 사람} 칩으로 나뉜다. 칩이 payload를 시각화한 것이다. 필요하면 각주에 미니 JSON을 단다.
- **KG**: Weaviate에는 cross-reference 기능이 있지만 덱에서는 쓰지 않는다.

## 2. 추천 스토리보드: 00 단계 장표 2개

### 공통 규칙 [제안]

- 연라벤더 배경에 보라 강조를 쓰고, 노랑은 쓰지 않는다.
- 노드-링크 선을 쓰지 않는다(KG로 오해받지 않도록).
- 확대 한 번에 기록 하나만 다룬다.
- 캡션은 초점 옆에 짧은 구로 쓴다. '폰' 대신 '기기'라고 쓰고, 절을 "·"로 잇지 않는다(기존 규칙).
- 기록은 앱마다 아이콘 하나씩 붙이고, 카카오톡만으로 채우지 않는다.
- 예시 문구는 자리표시자다. 실제로는 덱의 기존 시나리오 기록(예: C 버전의 면세점 단서 메시지)을 그대로 쓰는 편이 이야기가 이어진다.
- 띠 팔레트 예: #EFEBFF, #D4CBFF, #A996FF, #6B4EFF, #4B33C4(5단계). 03_지침·기획/디자인_규칙.md의 보라 값과 맞춘다.
- **진행 바 충돌**: 기존 결정은 "진행 바 01–04, 00 없음"이다. 그래서 00은 바가 나타나기 전 프롤로그로 두고 바에는 표시하지 않기를 권한다. 00을 바에 넣으려면 그 결정부터 다시 정해야 한다.
- **Morph 짝 맞추기**: 카드, 띠, 칩, 줄에 `!!카드_민지`처럼 !!로 시작하는 이름을 붙인다. Microsoft 안내: "begin an object name with !!"하고 두 장에 같은 이름을 쓰되, 한 장 안에서는 이름이 겹치지 않아야 한다. [확인]

### 장표 00-1 "기록 하나가 두 갈래로" (Morph 상태 4개)

| 상태 | 카메라 | 화면 | 캡션 | 근거 |
|---|---|---|---|---|
| 1 | 넓게 | 인트로처럼 흩어진 기록 카드 6~8장(카카오톡 메시지, 갤러리 사진, 메일, 캘린더 등). 카드마다 앱 아이콘 하나 | 흩어진 기록 | 기존 인트로 구름 |
| 2 | 카드 하나로 확대 | 메시지 카드 하나. 보낸 사람 아바타, 본문 한 줄, 앱 아이콘. 주변 카드는 흐리게 하고 옅은 딤 | 기록 하나 | One UI visual depth(blur+dim) |
| 3 | 고정 | 본문이 30% 정도로 옅어지고, 카드 아래로 12칸 띠가 왼쪽부터 자란다. 숫자는 처음 0.5초만 보였다 사라진다 | 뜻은 벡터로 | B1, B8(각주: 실제 768칸 예) |
| 4 | 고정 | 띠 아래로 칩 3개가 미끄러져 나온다: [11월 1일] [카카오톡] [민지]. 카드 오른쪽 위에 작은 자물쇠 | 단서는 그대로 | B2, B4, B7. 자물쇠는 B5, B6 |

### 장표 00-2 "모든 기록이 한 줄씩" (Morph 상태 4개)

| 상태 | 카메라 | 화면 | 캡션 | 근거 |
|---|---|---|---|---|
| 1 | 살짝 줌아웃 | 띠와 칩이 한 줄로 정렬되어 오른쪽 둥근 패널 "기기 안 색인"의 첫 줄로 들어간다. 줄 구성: [앱 아이콘] [12칸 띠] [날짜] [사람 또는 장소] | 한 줄로 저장 | B3, B4 |
| 2 | 고정 | 다른 카드들이 하나씩 날아와 줄이 된다. 갤러리 사진 줄의 칩은 [10월 25일] [갤러리] [연남동], 메일 줄의 칩은 [10월 30일] [메일] [예약센터] | 앱이 달라도 같은 모양 | B3, B5(2열), B6 |
| 3 | 패널로 줌아웃 | 줄 6~8개가 쌓인다. 같은 일에 관한 메시지 줄과 사진 줄은 같은 3개 열이 함께 진하다. 줄 사이에 선은 없다. 패널 배경에 아주 옅은 타일 텍스처와 자물쇠 | 질문이 오기 전에 미리 | B1(행 비교), B9(시각만) |
| 4 | 다음 단계로 | 질문 카드가 등장하고, 01–04 진행 바가 나타나며 01 단계로 넘어간다 | (없음) | 기존 덱 흐름 |

- **선택 버전**: 시간이 모자라면 00-2의 상태 3에서 줄들이 점으로 바뀌어 라벤더 평면에 흩어지는 장면 하나로 대신한다(B2, B10). 두 점을 선으로 잇지는 않는다.
- **각주 문구 예**: "실제 벡터는 수백 차원입니다 (예: Android ML Kit EmbeddingGemma 768차원). 그림의 12칸은 상징입니다." Weave가 실제로 쓰는 모델의 차원이 다르면 그 값으로 바꾼다.

## 3. 주의

- **KG**: 삼성 PDE는 지식 그래프 기반이므로 개념을 빌리지 않는다. Apple Photos 같은 다른 KG 사례는 목록에 넣지 않았다.
- **노랑**: Pinecone 그림의 노란 점은 보라로 바꾼다.
- **숫자**: 12칸은 상징이고 768은 ML Kit 예시다. Weave의 실제 모델 차원을 확인해 맞춘다.
- **시나리오**: 카카오톡 외 앱을 섞고, 메시지에 ㅠㅠ나 ㅋㅋ를 쓰지 않는다(기존 규칙).
- **진행 바**: 00을 표기할지 정해야 한다(2장의 진행 바 충돌 참고).
